Database migrations and seeding

Overview

- Alembic scaffolding has been added at the project root in the `alembic/` directory.
- The initial migration `alembic/versions/0001_create_all.py` will create all ORM tables (uses `Base.metadata.create_all`).
- Automatic table creation at engine init is now gated behind the `AUTO_CREATE_TABLES` flag (see `backend/settings.py`).
- Optional seeding is available via `scripts/seed_postgres.py` and can be run locally or automatically inside the backend container when `SEED_DB=true`.

Quick local setup

1. Install alembic (dev tool):

```bash
pip install alembic
```

2. Configure your environment variables (example):

```powershell
$env:DB_HOST='localhost'
$env:DB_PORT='5432'
$env:DB_NAME='ecommerce_db'
$env:DB_USER='user'
$env:DB_PASSWORD='<your-password>'
```

3. Run the initial migration (uses `backend.settings.Settings.DATABASE_URL`):

```bash
alembic upgrade head
```

Or generate an autogenerated revision:

```bash
alembic revision --autogenerate -m "add changes"
alembic upgrade head
```

Seeding the database

- To seed locally (runs the script against your DB):

```bash
python scripts/seed_postgres.py
```

- To have Docker seed on backend container startup, set the env var `SEED_DB=true` and (optionally) `AUTO_CREATE_TABLES=true` (for fresh DBs):

```yaml
# docker-compose.yml (backend environment)
AUTO_CREATE_TABLES: ${AUTO_CREATE_TABLES:-false}
SEED_DB: ${SEED_DB:-false}
```

Then:

```bash
docker compose up --build
```

Notes

- `AUTO_CREATE_TABLES=true` will call `Base.metadata.create_all()` during SQLAlchemy engine initialization. This is convenient for development but not recommended for production. Prefer Alembic migrations in production.
- The initial migration provided (`0001_create_all.py`) uses `Base.metadata.create_all()` for simplicity; you can replace it with explicit `op.create_table(...)` statements or use `alembic revision --autogenerate` to generate migrations from model changes.
